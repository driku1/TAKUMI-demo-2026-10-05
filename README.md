# TAKUMI — 製造ナレッジワークスペース

製造現場の暗黙知を、AIによる知識探索・専門家マッチング・深掘りインタビューを通じて形式知化するローカルデモです。

## 起動

Node.js 22.12以降（または対応する新しいLTS）を使用してください。

```sh
npm install
npm run dev
```

http://localhost:5173 を開きます。ポートが使用中の場合は、ターミナルに表示されたURLを使用してください。

```sh
npm test        # 知見の登録・活用とオントロジーグラフの自動テスト（Node組み込みテスト）
npm run build   # TypeScriptチェックと本番ビルド
npm run preview # ビルド結果のローカル確認
```

## デモ手順

1. 「Consultations」でサンプル質問を選択し、「Run agent」を押します。
2. 約16秒で検索 → 推薦 → 質問生成 → 模擬対話 → 回答を再生します。「Pause」で任意の段階を確認できます。
3. 左側のActivityでイベントを選ぶと、該当する中間出力を表示します。手動選択中は表示を固定し、「Follow live」で自動追従に戻せます。
4. 検索結果では取得記事・一致語と、製造オントロジー上の検索結果（Retrieval graph）、匠の推薦では登録24名から関連する上位5名・推薦理由と、候補者ごとのインタビュー後の想定ナレッジグラフ（Expected knowledge graph）、質問生成ではQ1〜Q3・直前の回答と、どの既存知見から何が未確認と判断して質問を作ったかのグラフ（Question rationale graph）を確認できます（下の「相談の各段階のグラフ」）。
5. 「Interview」でAgentと匠の対話、追加質問を確認し、「Design Response」で提案と回答根拠を照合します。
6. 「Knowledge PR」で新規記事の差分を編集し、出典・適用条件・重複候補の確認チェックを入れます。「Approve review」（模擬）後に「Merge knowledge PR」を押します。編集や追加対話は承認を解除します。
7. ライブラリの登録記事から、マージした本文・参照記事・対話・模擬レビュー履歴を確認できます。マージ後の知見は再読み込み後も残ります。
8. マージ完了後のKnowledge PR画面に「追加された知見と接続先」（補助オントロジーグラフ）が表示されます。接続は自動で、接続先を選ぶ操作はありません。
9. 同じ相談をもう一度した場合（サンプル質問の再実行や、キーワードで同じ相談に振り分けられる手入力）は、Mergeした知見そのものから回答します（推奨と適用条件を登録時の本文のまま引用。専門家の選定・インタビュー・登録PRは行いません）。登録した知見に関係する質問（サンプル「形状の量産時の注意点」、または手入力）で「Run agent」を押すと、Mergeした知見が検索でヒットした場合だけ、Design Responseの「登録知見の活用」に知見ID・本文の引用・確認事項と、ナレッジグラフ上で使われた箇所が表示されます。登録知見と既存ナレッジで確認事項をすべて根拠つきで示せる場合は、専門家の選定・インタビュー・登録PRを省き、「Knowledge retrieved → Registered knowledge found → Expert interview skipped → Response compiled」の数秒で回答します。足りない論点がある場合や未登録の場合は、従来どおり専門家インタビューに進みます（未登録なら登録知見を使ったことにはしません）。
10. Knowledge Graphで「① 登録前」「② 追加後」「③ 新知見に注目」「④ 回答での活用」を切り替えて比較します。②はテーマ全体の中で増えた点・線（NEW）を、③は追加した知見と接続先だけを拡大して強調し（ほかは薄く表示）、下に接続先の一覧を出します。①は表示の切替で、保存データは削除しません。④は表示中の回答がある間だけ選べます。

### 登録した知見を使う質問の例

画面上では1回目・2回目の区別をしていません。樹脂成形の例はサンプル質問「形状の量産時の注意点」で入力できます。ほかの2つは手入力します。

| 先に行う相談（Mergeする） | 次の質問の例 |
| --- | --- |
| 樹脂成形の品質ばらつき（リブ裏のヒケ） | 「この形状を量産する際の注意点は？」（冷却時の収縮差による反り、リブ周辺、ゲート位置、冷却回路のバランス） |
| 薄肉部品の加工変形 | 「薄肉アルミハウジングの派生品で、壁の形状が変わります。治具と加工工程で、事前に確認すべき点は？」 |
| 溶接後のひずみ | 「ステンレス製ブラケットの派生品で、溶接箇所が増えます。ひずみを抑えるために、事前に確認すべき点は？」 |

登録知見を「使った」と表示するのは、同じ相談または同じテーマで人が承認してMergeした知見が、今回の検索結果に入り、本文に該当箇所がある場合だけです。同じ相談を何度かMergeしている場合は最新のものを使います（検索で同点のときは新しくMergeした知見が先）。引用は保存された知見と既存ナレッジの本文から取り出します（樹脂成形の例では、冷却回路のバランスを既存ナレッジ seed-2-7「金型冷却回路の偏りを、成形品の反りと結びつける」で補います）。専門家の回答はデモ用に準備した内容で、AIの生成結果ではありません。

### Knowledge Graph（オントロジー）

AutomotiveSummitデモの `ontology-v0.04.html`（ダッシュボードにiframeで埋め込まれているオントロジー画面）の構造・表示・操作を移植しています。

- 組織オントロジー（Company / Division / Department / Team / 匠）と、製品・ナレッジオントロジー（工程領域 / 対象部品 / 技術・観点 / ドキュメント / 登録知見）に分けて表示します。
- グラフに追加されるのは、人がApprove reviewしてMergeした知見だけです。相談や回答はグラフに保存しません（元の相談は登録知見の詳細に来歴として表示）。
- 「④ 回答での活用」は、表示中の回答がどの登録知見を使い、どの技術・観点に当てたかを、承認済みのグラフの上に重ねて表示します。点や線は追加されず、回答を閉じる（New consultation）と消えます。
- 左側のパネルに表示レイヤーと、線の種類ごとの見本（色・実線／点線）と意味を表示します。ノード選択と関連強調、詳細パネル（コンテキスト・概要・登録内容・関係一覧）、ホイール拡大縮小・ドラッグ移動・ボタン操作、文字サイズ切替に対応します。
- 線には「配下」「所属」「担当」「執筆」「対象部品」「確認観点」「参照」「承認（模擬）」「発展元」などの名称があります。実線は登録された関係、点線は語の一致（「タグ一致」「本文で言及」。因果関係ではない）、丸い点線は④の一時表示（「回答で使用」）です。
- 「NEW」（紫）はMergeで増えた点・線、「USED」（橙）は表示中の回答が使った登録知見と関係です。NEW・USEDは色と太さだけを変え、実線／点線の意味は変えません。
- ノード・関係・件数・詳細は `src/ontology.ts` の同じ関数から作成し、ホーム画面のカード、Knowledge Graph画面、マージ後・回答の補助グラフ、相談の各段階のグラフで共通です。

### 相談の各段階のグラフ（一時表示）

Knowledge Graphと同じ承認済みのオントロジー（`src/ontology.ts`）から、各段階に関係する部分だけを読みやすく並べ直して表示します（`src/StepGraphs.tsx`）。どれも表示中だけの一時表示で、グラフ・保存データには何も追加しません。実線は登録済みの関係、点線・破線は一時表示です。

| 段階 | 見せるもの | 一時表示の線・点 |
| --- | --- | --- |
| Knowledge Search（Retrieval graph） | 何を取得したか。右に検索結果（一致した語が多い順に上から。順位・点数は表示しない）、左に一致した語の技術・観点ノード（テーマ全体の語は工程領域） | 青緑の点線「検索語一致」（語の一致で、因果ではない）。既存のタグ一致などの関係があればそれを強調 |
| Expert Matching（Expected knowledge graph） | 候補者ごとに、その人にインタビューした場合に追加が想定される知見（未登録）と接続先。カードの「想定グラフ」またはタブで切替 | 紫の破線「回答者・対象部品・確認観点・工程領域・参照候補（想定）」と、破線枠の「想定される知見」1件 |
| Question Plan（Question rationale graph） | なぜその質問を作ったか。左に参照した既存知見（強調）と直前の回答、中央に確認したい点、右に生成した質問 | ピンクの点線「参照した既存知見」「直前の回答」「質問を生成」と、点線枠の「確認したい点」「生成した質問」 |

- 想定グラフは、候補者の専門領域タグ・担当業務の説明・検索で見つかった本人の知見から作ります。回答の内容を予測するものではなく、AIの生成結果でもありません。実際にグラフへ入るのは、インタビュー後の登録PRをApprove・Mergeした内容だけです。
- 質問計画のQ1は、検索結果を確認しても残る不足（Knowledge gap）から作られ、Q2以降は直前の匠の回答と、質問の観点に近い取得知見から作られます。生成済みの質問だけを表示します。
- 検索結果のうち、このテーマのグラフにノードがないもの（別テーマの登録知見など）は線にせず、一覧で示します。

PRはローカルで再現した登録フローです。GitHubなど外部のPR作成や実際の専門家への連絡は行いません。未マージのドラフトと実行状態はページ移動中は保持しますが、再読み込みするとリセットされます。

ナレッジグラフのノード選択・拡大縮小、専門家のプロフィール表示、専門家起点での相談、検索、ライブラリの絞り込みにも対応しています。

初期ナレッジは40件です。製品設計・工程設計・製造・品質改善を横断し、公差、治具、加工順序、溶接、成形、測定、再発防止などの架空事例を収録しています。各事例で判断のポイント、実施事項、適用条件を確認できます。既存のブラウザでも再読み込みすると新しい初期データが反映され、保存済みのインタビュー知見は保持されます。

Expertsは24名・6領域の架空プロフィールを収録しています。専門領域フィルター、氏名・ローマ字・専門タグの検索、相談できる内容の確認に対応します。新しいプロフィールからは関連ナレッジを参照でき、模擬インタビューは従来の3名・3シナリオと、登録知見を使う質問（上の表）で再生します。

## Codexスキルで進めるデモ

Codexデスクトップアプリ（Windows）の左側チャットで6つのスキル（`$takumi-launch` → `$design-consultation` → `$expert-matching` → `$interview-plan` → `$expert-interview` → `$knowledge-pr`）を順番に呼び出すと、右側の画面が次の工程へ進みます。登録PRの Approve review と Merge は人が画面で行います。同じ相談や登録知見で答えられる相談は、`$design-consultation` が自動で登録知見だけから回答します。準備・台本・仕組みは `CODEX_DEMO.md` を参照してください。

```sh
node scripts/install-codex-skills.mjs   # スキルをCodexに入れる（初回・フォルダー移動後）
node scripts/reset-demo.mjs            # 録画前に初期化（npm run demo:reset）
node start-demo.mjs --skills           # スキル連携のデモサーバー（npm run demo:start。最初のスキルが自動起動もする）
```

## デモの範囲

- 実際のAI APIや社内システムへの接続はありません。外部への依頼・メッセージ送信は行いません。
- 薄肉アルミ加工、ステンレス溶接、樹脂射出成形の3種類の架空シナリオと、それぞれの知見を使う質問（上の表）を用意しています。自由入力はキーワードでシナリオを選び（「量産」「ゲート位置」「冷却回路」などは形状の量産時の注意点、「派生」は各テーマの派生品の相談）、一致しない場合は薄肉アルミ加工の参考シナリオになります。
- 検索は実際の初期・保存済みデータへの語句照合です。タグ4点・タイトル3点・要約1点の合計を使用し、AIの確信度ではありません。匠の対話担当は選択されたシナリオの担当者です。
- 登場人物、経験年数、対話、レビュー、ナレッジはサンプルです。技術提案は実用前に専門家のレビューと検証が必要です。
- 添付は最大5件、各20MBです。ファイル名のみ画面に表示し、内容の解析・アップロード・永続保存は行いません。
- ナレッジの保存先はブラウザのlocalStorage (`takumi-knowledge`) です。回答で登録知見を使った情報は表示中だけの一時情報で、保存しません。初期状態に戻すにはブラウザの開発者ツールでこのキーを削除してください。10-04版で保存した知見（`scenarioId` なし）は、タグがシナリオと完全一致する場合に、そのテーマの登録知見として扱います。
- WebフォントのみGoogle Fontsから読み込みます。未接続時はシステムフォントにフォールバックします。

## 構成

- React / TypeScript / Vite
- `src/data.ts`: 専門家、シナリオ、対話、初期ナレッジ
- `src/expert-seeds.ts`: 追加専門家21名のプロフィール
- `src/knowledge-seeds.ts`: 分野別の追加ナレッジ37件
- `src/App.tsx`: 画面、デモフロー、保存・書き出し、表示中の回答の活用情報（保存しない）
- `src/ProcessWorkspace.tsx`: 工程別出力、実行ログ、登録PRと模擬レビュー、登録知見の活用表示、回答とマージ後の補助グラフ
- `src/process-model.ts`: 記事検索、候補の照合、質問の生成根拠
- `src/knowledge-cycle.ts`: 登録知見の特定、同じ相談・知見を使う質問の検索・引用・確認事項、活用情報の検証、登録処理
- `src/ontology.ts`: 製造オントロジーのノード・関係・段階（①〜④）・件数・配置・関係名の配置
- `src/OntologyGraph.tsx` / `src/ontology-graph.css`: オントロジーグラフの表示と操作（参考デモから移植）
- `src/StepGraphs.tsx`: 相談の各段階（検索・匠の推薦・質問生成）のグラフ
- `src/skill-runtime.ts`: Codexスキル連携（デモサーバーの状態に画面を追従させる）
- `skills/`・`scripts/`: Codexスキルの定義と処理（`CODEX_DEMO.md`）
- `src/styles.css` / `src/process-workspace.css`: レスポンシブスタイル
- `tests/`: `npm test` で実行する自動テスト

実サービス化では、既存知識の検索、専門家の権限・稼働確認、本人の同意を得たインタビュー、専門家レビューを伴う知識登録を、それぞれバックエンドに接続してください。
